# 2026-10-21 REA 接入验收

## 核验对象

实际接入 [morluto/rea](https://github.com/morluto/rea) 发布的 `rea-agents@6.7.0`。工作方法先核对已安装包内 Skill、JavaScript 工作流及 CLI 输入 schema，再实现界面。方法说明见 [REA-WORKFLOW.md](../../REA-WORKFLOW.md)。

本轮实现本地 JavaScript / Electron 目录和 ASAR 的静态概览、真实应用图追踪，以及基于证据的 AI 解读、重建方案入口。网页 CDP、原生二进制和动态运行分析不在本轮范围内。后两个 AI 步骤复用现有助手链路；本轮不执行付费模型请求。

## 从用户角度提出并验证的问题

| 用户问题                                     | 实现与验收依据                                                                                                                |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 换一个首页工序，输入框会不会越加越长？       | 正式 GuidPage 和离线 Demo 都改为替换。覆盖连续切换、重复点击、保留附件、发送期间禁用。                                        |
| 没配模型，能否先取得真实证据？               | 概览和追踪通过本地 REA CLI 执行，不创建 AI 会话；界面区分工具步骤与模型步骤。                                                 |
| 这是静态发现，还是目标已经运行过？           | Fixture 主入口含无条件异常；扫描仍成功，证据明确记录未执行 bootstrap。界面持续展示静态范围及局限。                            |
| 追踪的是什么，能否核对原始依据？             | 必须选择概览返回的真实 node ID 和方向。追踪复用原始 Evidence，保留源 ID；原始下载按字节数和 SHA-256 核对。                    |
| 结果还没出来就切换区域、点击停止，会怎样？   | 测试发现后台更新 revision 后停止返回 409。已改为停止请求绑定当前 run 并优先通知取消，随后记录状态；覆盖进程清理和停止后重试。 |
| 修改问题是否还要重新扫描同一个包？           | 保留概览，使旧追踪及下游过期，清空选择，要求按新问题重新选择线索。更换目标会使概览及所有下游过期。                            |
| 历史证据会不会被编辑成“成功”？               | 工具成果只读，历史可查看及下载；原始文件丢失、篡改或来源不符会明确失败。                                                      |
| 转去加工会不会直接运行模型或带入未保存草稿？ | 创建独立生产项目，只使用所选已保存版本，并携带来源引用；不触发模型执行。                                                      |
| 路径无效、工具未安装、版本不符能否恢复？     | 分别展示错误与配置说明；重新检查后恢复可执行状态，不生成虚假证据。                                                            |
| 小窗口是否还能操作？                         | 检查 390px 宽度，验证无页面横向溢出；截图保存在 screenshots/。                                                                |

## 中途失败与处理

1. 桌面检查发现停止请求返回 409，根因是后台进度先更新 revision。已修复运行控制与取消信号的顺序，并用真实停止、无成果落盘和重试测试复验通过。
2. macOS 原生下载未通过 Playwright 的页面下载事件报告。测试改为由 Electron 原生下载事件保存文件，仍从界面点击真实下载入口，并检查实际文件字节数、散列和 Evidence ID。
3. 一个测试在后端已完成、界面尚未收到新版本时打开历史下拉，菜单被界面刷新替换。补上“界面已显示 v2”的前提后，历史查看和下载多轮通过。
4. 一轮测试未取得主窗口并超时，未进入功能验证。独立冷启动约 4 秒通过，之后完整验收及重复运行均成功。该次超时原因未确认，没有将它记成通过。
5. 后端扩展全工作区首次运行在未修改的 Office 端口超时测试失败。独立完整 Office 测试默认并行 104 项、串行 104 项和该单项均通过。测试先分配再释放端口，再假定没有监听者；并发端口复用是有代码依据的可能原因，未捕获当时占用者，不能认定已确认根因。没有因此修改 Office 业务源码，也不把这次全量运行写成一次全绿。
