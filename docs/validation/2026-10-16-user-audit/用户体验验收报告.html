产出质量另有改进空间：第一工序同时输出后续工序内容，第三工序未遵守 300 字预算。建议每道工序限定成果结构与长度，生成后校验，减少重复和阅读成本。第三工序交付的是开发任务文档，不能等同于应用已开发完成。

整改清单

优先级用户会问证据与问题整改方案验收标准证据
P1我刚修改的内容，为什么验收和导出还是旧的？现场复现：保存 v1，输入 v2 不保存，点击人工验收通过。页面显示 v2 和已验收，导出交付文档却是 v1。将验收绑定明确的成果版本；有草稿时提供“保存并验收”，导出前明确保存或舍弃。页面显示未保存标记。修改→验收→导出内容一致；切换旧版本后也能明确知道验收的是哪一版。unsaved-approval.png / export-with-unsaved-draft.md
P1（优先复核）为什么点助手和模型没反应？当前 macOS 桌面界面中，鼠标点击选择框仅聚焦，未展开；按回车可以展开。复测助手选择仍如此，尚未定位根因。检查 label 包裹 Select 导致的事件转发、焦点与弹层关闭逻辑；补鼠标及键盘交互回归。助手和模型都能单击展开、选择、保存并重新打开确认。原生界面交互记录；环境相关问题，需进一步定位
P2API 已配好，为什么新项目不能开始？只填名称和资料可以创建项目，但助手为空，执行按钮禁用，要求再编辑。默认选择已可用的助手与模型；创建页做可执行性检查。需要保留空配置时明确标为草稿。普通用户输入想法后可直接开始；没有模型时准确引导配置。原生新建项目实测
P2HTML 明明有了，为什么看不到原型？有效原始 HTML 无预览按钮；只加 html Markdown 代码围栏，同样内容就能预览，按钮点击成功。支持原始 HTML 和代码块两种输入，长期使用带类型的成果对象；识别失败给出提示。两种格式均可预览和下载，保留隔离运行限制。raw-html-no-preview.png
P2中文项目名为什么能输入却不能保存？前端允许 100 字符；API 实测 66 个相同汉字成功，67 个失败（400）。后端按 200 UTF-8 字节限制。前后端统一字符计数与长度；显示剩余字数和字段错误，覆盖中文与 emoji。界面允许提交的名称不会因同一长度规则被后端拒绝。name-boundary.json
P2我应该从首页四张卡片开始，还是另建生产项目？首页工序卡片只填聊天输入框，真正持久化四工序在另一个生产项目入口。侧栏还显示内部 UUID 目录。首页主要入口统一为新建生产项目；聊天快捷卡标明用途；用产品名称分组工序会话。第一次使用能找到主流程，不需要理解目录 ID、助手或会话的区别。首页和项目页面现场走查
P2没有验收项，怎么就能全部通过？手工夹具 checks=[]，四阶段保存内容后可全部 approve。只表示允许人工确认，并不证明真实成果合格。最终交付前要求填写可检验条件，或明确确认跳过并记录原因；展示人工验收和自动测试的区别。无法无提示地把空清单当作完成质量验收；每项可关联结果与证据。empty-checklist.json（手工夹具，已归档）
P2生成到哪了，为什么还要我点工具授权？进度条表示人工验收数量，生成过程中仍为 0%；第三阶段需读取工作目录授权，已有提示和跳转可用。生成与人工验收进度分开；显示当前动作、耗时和等待原因。提供仅生成方案/读取项目开发模式，按模式启用工具。用户能区分生成中、等待授权、待验收；无需猜测是否卡住，不绕过权限机制。真实 MiMo 连续流程现场观察
